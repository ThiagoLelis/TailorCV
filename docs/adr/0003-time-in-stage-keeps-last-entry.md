# Time in Stage keeps only the last entry into each Stage

When the board moves an Application, it records when the Application entered the Stage as a frontmatter field (`applied_at`, `in_process_at`, `offer_at`, `closed_at`; Awaiting Application uses `created`). Each field holds only the **last** entry, and entering a Stage deletes the fields of every Stage after it in the order awaiting → applied → in-process → offer → closed. We chose this over a full transition history because the frontmatter is flat `key: value`, moving back is rare (usually a mis-click), and a history would need a list format or a second file. Without the deletion, moving back would leave later entries in place and produce stale or negative durations. The cost: an Application that goes back and forth loses the time spent on earlier passes, and folders moved by hand in the file explorer (see 0002) are not timestamped at all.
