# Board order is Fit by default, with a sparse `position` for cards placed by hand

Each column is ordered by Fit (highest first, newest first within a Fit), and the user can drag a card to a specific spot where it stays across reloads. A card placed by hand stores a `position` number in its `application.md` frontmatter. Both share one scale: a card without a `position` sorts as if it had `10 × (6 − Fit)` (Fit 5 → 10, Fit 1 → 50, no Fit → 60), so lower means higher in the column. Placing a card gives it a value between its neighbours' keys, so usually only that card's file is rewritten, and new Applications (from the CV skill, or folders moved by hand per 0002) slot in by their Fit around the cards the user placed, so the skill never needs to know about order. When the neighbours share a key (two unplaced cards with the same Fit) or the floats run out of room, the cards in that stretch are spread evenly between the keys around it, which keeps them inside their Fit's band. Moving an Application to another Stage without a drop spot (the Stage selector) removes its `position`, so it takes its Fit's spot there. "Sort by Fit" on a column removes every `position` in it.

We chose this over a single `board_order.json` because a separate file falls out of sync whenever folders are created, moved or deleted outside the board, and it would compete with the Application's own file as the source of truth (0001). We also rejected browser `localStorage`, which lives outside the files and is lost when you switch browsers. The cost: a placed card keeps its spot even if its Fit is later changed, positions are only meaningful within one column, and a card dropped into another column gets a new `position` there.
